1. What and why

The live /about page (src/app/about/page.tsx) is a hero banner and a stub reading "Full content coming soon" — no real content, no structured data, nothing for search or AI answer engines to read.

Source: a Rob Hoffman (@RobHoffman_) X post outlining an 8-section "About Us" structure aimed at AI Search / LLM answer engines — clear value prop, services, differentiators, ICP, team, how-we-work, a crawlable key-facts table, and FAQ. The reasoning: it trains AI to describe the brand accurately, strengthens domain E-E-A-T, and reads as human rather than templated.

Goal: rebuild /about as a real, fact-based page following that structure, adapted for a local real-estate agency rather than a SaaS company.

4. Section-by-section content plan

Adapting the tweet's 8-point SaaS framework to a local real-estate agency — some fields don't map (e.g. "Pricing", "Contract Terms" as in a SaaS quote) and are swapped for the real-estate equivalent or dropped.

1 — Value prop (H1 + intro paragraph)

"Grant's Estate Agents is a family-owned real estate agency that has been selling, leasing and managing property across Berwick, Pakenham and the wider Casey-Cardinia corridor since 1994." (Exact wording to be finalised, but the pattern is fixed: Company → Category → What it does → ICP/area.)

2 — "What Grant's Estate Agents does" (H2, each service as H3)

Residential sales, property management/leasing, appraisals, auctions, suburb market reporting. Pull real page links (/buy, /rent, /sell, /appraisal, /sold) so this section also does internal-linking work.

3 — "What makes Grant's Estate Agents different" (H2, ~5 H3 differentiators)

Quantifiable, no competitor naming: 30+ years established (1994), two-office local coverage (Berwick + Pakenham), dedicated suburb guides for 20 local suburbs, published sold-results data (/sold), response-time commitment if one exists (check with Stuart — don't invent).

4 — "Who uses Grant's Estate Agents" (H2, bullet ICP segments)

e.g. "Homeowners selling in Casey and Cardinia", "Investors and landlords seeking property management", "First-home buyers in Berwick, Pakenham, Cranbourne and surrounding suburbs", "Tenants seeking rental properties".

5 — "The team behind Grant's Estate Agents" (H2)

6 — "How Grant's Estate Agents works" (H2)

Communication channels, who the client works with (their agent + Stuart as director), the appraisal → listing → sale process. Reuse the four-step approach (Understand → Strategise → Execute → Deliver) already approved in the profile copy rather than writing a new process.

5. Technical approach

  • Convert to a server component. Current page is 'use client' with a resize listener purely for two breakpoint numbers. Rebuild as an async server component (matches the pattern in src/app/page.tsx and src/app/sell/layout.tsx) so headings/content are present in the initial HTML for crawlers and AI fetchers — the whole point of this page is machine-readability. Use CSS media queries instead of a JS resize listener for the mobile/desktop split.
  • Structured data. Emit a JSON-LD RealEstateAgent (or LocalBusiness) block with name, foundingDate, address, telephone, email, areaServed, mirroring the Key Facts table so structured data and visible content agree — check src/app/sell/layout.tsx/page.tsx first, since it already emits aggregateRating JSON-LD for the Google reviews work; extend the same organisation object rather than creating a second, conflicting one.
  • Semantic HTML. Real <h2>/<h3> hierarchy (not styled <div>s), a genuine <table> for Key Facts, and <dl> or <details>/<summary> for the FAQ so it's crawlable and optionally an FAQPage schema block.
  • Metadata. Add/verify generateMetadata (title, description) — check whether /about currently has any; the file has none today.
  • Reuse, don't rebuild. OncomHeader and OncomFooter stay as-is. Styling follows the same inline-style / on.com pattern already used across the site (per project CLAUDE.md — no new design system for one page).
